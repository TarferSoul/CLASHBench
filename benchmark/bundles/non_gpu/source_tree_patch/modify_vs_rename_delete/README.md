# Source-tree path-lifecycle conflicts

This staging bundle contains two paired A+B samples for the approved
`source_tree_patch/modify_vs_rename_delete` mechanism. Each case uses a real Git
checkout in which A has a useful tested rename staged while B must implement a
different concrete deliverable at the exact old path.

The root-owned runner exposes only `/work`, the selected task text, optional
authorization files, and the ordinary checkout/process surfaces to `agentb`.
Private setup, reference changes, trust records, graders, evidence, and bundle
source remain unreadable.
